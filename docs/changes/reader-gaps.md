# Reader gaps found while porting the e2e specs (refactor phase 2b, session 1)

Each row is a test that checked something Original layout did and the new reader (`src/quietReader`) does not. The test is kept as `test.fixme` with a one-line reason, so it still documents the behaviour. Session 2 decided each (last column); the accepted losses are also in the change matrix (`refactor-changes.md`, phase 2b).

| Spec | Test | What Original layout did | Why the new reader can't | Suggested resolution | Decision (session 2) |
| --- | --- | --- | --- | --- | --- |
| `footnotes.spec.ts` | footnote popup keeps safe markup and drops script source from the note | The note popup showed the note's sanitised markup (a `<b>` stayed bold) and left out a `<script>`'s source. | The new reader keeps a note as plain text (`noteText` in `src/readerCore/parseCleanEpub.ts` takes `textContent`), so the markup is gone and a `<script>`'s source text shows in the note. | Close the gap for the script text (skip `script`/`style` in `noteText`, a one-line fix). Accept the loss of bold and italic in notes. | **Script part closed** (8fe3023: notes skip script and style; the check runs again as its own test). **Bold: accepted loss**, test renamed "keeps safe markup from the note" and left fixme. |
| `footnotes.spec.ts` | an unresolvable footnote target shows the "Go to note" fallback | A note that could not be loaded inline said so and offered a "Go to note" button to follow the link in the book. | The new reader says "This note could not be found in the book." and offers "Go to note" only when the note's text can be found in the chapter (`noteTarget` in `QuietReader.tsx`). A broken link has nowhere to go. | Accept the loss: the message is honest and the button would have nothing to open. | **Accepted loss.** |
| `reading-layout.spec.ts` | page-turn buttons are labelled Previous and Next (was the first half of "nav labels, Paged/Scrolling layout toggle actually scrolls, and persists") | Each page-turn button had a visible text label ("Previous", "Next") under its arrow. | The new reader's page-turn buttons are arrows only (`TurnButtons` in `src/quietReader/Chrome.tsx`); the name is an aria-label and a tooltip. | Accept the loss: the arrows are named for screen readers and the tooltip says what they do. | **Accepted loss.** |
| `untrusted-epub.spec.ts` | each section carries a script-src 'none' content security policy (was the last check of "scripts embedded in an EPUB never run, and word taps still work") | Each section iframe had a `Content-Security-Policy` meta forbidding scripts, on top of the sanitiser. | The new reader has no section iframe. It draws a book as escaped plain text, so a script, handler, frame or image from the book never reaches the page (the ported test checks that). | Accept the loss: there is no frame to sandbox. | **Accepted loss** (nothing left to protect: no frame, and book markup never reaches the page). |
| `vocab-levels.spec.ts` | Vocab Levels: the panel collapses to a strip and expands again (was a step of "rarity data, tier switching, jump-to-word, export, and Settings status") | The Vocab Levels panel had a collapse button that folded it to a thin strip, and an expand button that opened it again. | The new reader's margin panel (`MarginLevels.tsx`) only opens and closes. The ported test also checks the jump button's "1 of N" title where the old one checked the occurrence stepper. | Accept the loss: closing and reopening does the same job, and the dock's Levels button reopens it. | **Accepted loss.** |
