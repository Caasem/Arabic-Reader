# Building the Android app

This `android/` folder is a real, self-contained Gradle/Android Studio
project generated by Capacitor (`npx cap add android`) — it wraps the same
`dist/` web build used by the PWA and Electron desktop builds in a native
WebView shell. There is **no dependency on Google Play or Play Services**
anywhere in this project: no Play Billing, no Firebase, no Play-Asset
Delivery. The output is a plain `.apk` you install by sideloading (copying
it to a phone and opening it, or `adb install`), the same way you'd install
any APK from outside the Play Store.

Building it does require the Android SDK and a network connection that can
reach Google's Maven repo (`dl.google.com`) and Maven Central — the sandbox
this project was developed in blocks both, so the actual compile step has
to happen somewhere with normal internet access: your own machine, or CI
(see the GitHub Actions workflow below). The Gradle configuration targets
Android API 36 and Java 21.

If Android Studio reports that `:capacitor-android` has no matching
variant, open **Settings → Build, Execution, Deployment → Build Tools →
Gradle** and set **Gradle JDK** to a Java 21 installation. Android Studio
2026 may bundle Java 25, which is newer than this project's Gradle 8.14.3
and Android Gradle Plugin 8.13 toolchain and can prevent the Capacitor
library project from being configured correctly. From the repository root,
run `npm install` followed by `npx cap sync android` before reopening the
`android/` project.

## Option A — Android Studio (easiest)

1. Install [Android Studio](https://developer.android.com/studio) (it
   bundles the Android SDK, so you don't need to install that separately).
   Ensure the Android 36 SDK platform/build-tools and a Java 21 JDK are
   available.
2. Open this project's `android/` folder directly in Android Studio
   (`File → Open`, point it at this folder, not the repo root).
3. Let it finish its first Gradle sync (this is the step that needs
   internet access — Android Studio will fetch the SDK platform/build-tools
   and all the Gradle/Maven dependencies automatically).
4. `Build → Build Bundle(s) / APK(s) → Build APK(s)`. The finished file
   lands at `android/app/build/outputs/apk/debug/app-debug.apk`.
5. Copy that `.apk` to a phone (email, USB, cloud drive, `adb push` —
   anything) and open it there. Android will ask to allow installing from
   this source the first time; that's the normal sideloading prompt, not an
   error.

For a release build (smaller, optimized, and required if you ever want to
distribute it more widely rather than just installing it on your own
device), use `Build → Generate Signed Bundle / APK` instead, which walks
you through creating a signing key — keep that key file somewhere safe,
you'll need the *same* one for every future update to this app.

## Option B — command line, if you already have the Android SDK installed

```sh
cd android
export ANDROID_HOME=/path/to/your/android/sdk   # wherever your SDK lives
./gradlew assembleDebug
```

Output: `android/app/build/outputs/apk/debug/app-debug.apk`.

On Windows, run `gradlew.bat assembleDebug` from the `android/` directory
instead. From the repository root, `npm run android:build` selects the
correct Gradle wrapper automatically.

Whenever the web app itself changes (any edit under `src/`), rebuild and
re-sync before building the APK again:

```sh
npm run build
npx cap copy android
```

(`npx cap sync android` also works and additionally re-checks installed
Capacitor plugins — copy is enough for this project since it doesn't use
any native plugins beyond the Android shell itself.)

For an attached emulator or device, use `npm run android:run`; for Android
Studio, use `npm run android:open`.

## Option C — GitHub Actions (no local Android Studio at all)

See `.github/workflows/build-android.yml` at the repo root. Push this
project to a GitHub repository and it builds a debug APK on every push,
attaching it to the workflow run as a downloadable artifact — this is the
path that needs no local Android tooling whatsoever, since GitHub's hosted
runners already have the Android SDK preinstalled and unrestricted
internet access to fetch everything else.

## App identity

- Package name (`appId`): `org.arabicreader.app` — set in
  `capacitor.config.ts` at the repo root. Change it there (not in the
  `android/` folder directly) and re-run `npx cap sync android` if you ever
  need a different one; note that changing it after your first real install
  makes Android treat it as a different app (won't upgrade in place).
- App icon: generated from `icon128.png` (the project's existing PWA icon)
  into every `android/app/src/main/res/mipmap-*` density, including a
  centered adaptive-icon foreground layer over the app's own cream
  background color (`#FAF7F2`, matching the PWA manifest's theme).
